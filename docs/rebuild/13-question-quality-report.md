## Priority corrections

Short-answer tolerance and unit stripping require explicit question policy. Merely supplying a unit does not authorize removing it. Case-sensitive and whitespace policies are honored. Browser local practice uses the same evaluator instead of parseFloat with a hidden tolerance. Missing answer keys are not assigned option A/true or converted to the string “undefined”. Loader no longer labels bundled records published/verified on an unsubstantiated boolean flag.

Candidate validation covers schema, subject/grade, answer structures, duplicate options, formula delimiters/braces, markup and unsupported assets. Topic mapping is required at review; curriculum/skill correctness is a human review obligation, not inferred from parser output. Images/MathML/tables/graphs that lack integrity support are blocked rather than silently discarded and published. Published API responses strip raw source, audit details, explanations and answer keys.

Verification requires configured authorization and substantive evidence; publishing requires source permission and verification evidence. The fixture reviewer is named `fixture-reviewer` solely in tests; no actual teacher review or real-source publication occurred. Full semantic formula validation, automated pedagogical checking and curriculum knowledge graph matching are not implemented.

Local result persistence is idempotent by session ID. Trusted server sessions separately snapshot server-owned questions and persist their aggregate result once. These local guarantees do not extend to multiple worker processes or Vercel without a database transaction backend.
